# kr-grant-trace 설계서 (2026-10-20)

## 한 문장

한국 정부 R&D 과제번호(NRF·RS 통합번호·IITP·KEIT·KETEP·KHIDI·NST·IPET 등)를 받아 OpenAlex에서 그 과제의 사사(acknowledgement)가 달린 논문을 찾고, 사업 단위로 묶어 세되, **못 찾은 것을 못 찾았다고 보고하는** 명령줄 도구.

## 왜 필요한가

- 사업 평가에서 "이 사업에서 논문이 얼마나, 어떤 질로 나왔나"를 NTIS 자기 보고가 아닌 외부 색인으로 재는 수단이 없다
- OpenAlex에 한국연구재단 과제번호가 달린 논문이 335,554건(2026-10-20 실측) 있지만 표기가 제각각이라 그대로는 못 쓴다
- 기존 시도(`eumsoohong/ntis_matching`, `kangdacool/ntis-*`)는 절차나 단일 주제 분석이고 범용 매처가 없다

## OpenAlex 쪽 사실 (2026-10-20)

- `works?filter=awards.funder_award_id:<정확한 문자열>` 작동, `|`로 OR 가능 → 변형 전개 뒤 한 번에 질의
- 변형마다 award 엔티티(G-id)가 따로 있음(`2016R1A2B4014600`과 `NRF-2016R1A2B4014600`은 다른 G) → 번호 정규화 없이는 같은 과제가 쪼개짐
- awards 엔티티의 `search`는 번호를 못 찾음(0건) → 정확일치만 믿는다
- cursor 페이징 정상, `select`로 필드 축소 가능
- 숫자만인 번호(8·10·14자리)는 다른 나라 번호와 충돌 → 한국 펀더 `funders.id` 필터를 함께 건다

## 명령

| 명령 | 입력 | 출력 |
|---|---|---|
| `normalize` | 번호(들) 또는 파일 | 정규형·유형·연도·질의 변형 목록·메모(무엇을 벗겼는지) |
| `trace` | 번호(들)/CSV 열 | 논문 표(DOI·연도·유형·인용·FWCI·OA·국제공저·주제·매칭된 번호) + 번호별 건수. 캐시(SQLite) |
| `summarize` | trace 결과 | 과제·사업코드·연도별 집계(논문 수·인용 중앙값·FWCI 중앙값·국제공저율·OA율). 중복 계수 규칙 `--credit full|split|first` 명시 |
| `coverage` | NTIS 성과 목록 CSV(DOI·과제번호 열) | 매칭률(**하한**)과 미매칭 사유: DOI가 OpenAlex에 없음 / 있으나 사사 없음 / 사사는 있으나 다른 번호 / 번호 미해석 |
| `selftest` | — | 정규화 회귀 + 자체 점검 |

## 정직성 규칙

1. 매칭률은 항상 "하한"이라 쓴다 — 사사를 안 쓴 논문은 영영 못 잡는다
2. 한 논문에 과제 n개가 달렸을 때의 계수 규칙을 출력 머리에 적는다(기본 `full`: 각 과제에 1)
3. `UNPARSED`는 질의하지 않고 따로 센다. "0건 ≠ 성과 없음"
4. 사업 코드(NRF `R1A2B4` 같은 조각)에 사업 이름을 붙이지 않는다 — 코드 조각만 보여 주고 이름은 사용자가 붙인다
5. 캐시된 결과는 조회일을 같이 쓴다. OpenAlex는 매주 바뀐다

## 의존

표준 라이브러리만. HTTPS는 urllib → certifi → curl 3단(python.org 파이썬의 인증서 함정). polite pool용 `OPENALEX_MAILTO` 환경변수.

## 하지 않는 것

- Scopus·Dimensions 백엔드(키 필요) — 2차
- NTIS API 직접 호출 — 사용자가 NTIS에서 내려받은 CSV를 받는다(키·약관 문제 회피)
- 특허·기술료 — 논문만
